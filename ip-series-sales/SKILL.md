# IP多弹次系列销售分析

## 使用流程

1. 确认用户提供了多弹次销售数据CSV文件路径
   - 必需列：`下单时间`, `用户ID`, `用户注册时间`, `弹次名称`, `消费金额`
   - 编码支持：GBK / UTF-8
   - 弹次名称格式示例：`IP名称 第1弹`, `IP名称 第2弹`
   - 最后一只弹次将被自动识别为分析基准（新弹次）
2. 使用 `scripts/generate_report.py` 生成分析报告
3. 将生成的Markdown报告交付用户

## 核心脚本

### generate_report.py — 报告生成器

Python脚本，读取多弹次销售CSV数据，按标准分析框架计算指标，输出结构化Markdown报告。

**必需参数：**
- `--csv <路径>` : 多弹次销售数据CSV文件路径

**可选参数：**
- `--output <目录>` : 报告输出目录（默认当前目录）

**用法：**
```bash
python3 scripts/generate_report.py --csv /path/to/data.csv --output /path/to/output
```

**示例：**
```bash
python3 scripts/generate_report.py --csv "奥特曼立体卡牌手办各系列销售数据.csv" --output ./报告目录
```

## 数据字段要求

CSV必须包含以下列（列名精确匹配）：

| 列名 | 说明 | 示例 |
|------|------|------|
| `下单时间` | 订单时间，格式 `YYYY/M/D HH:MM` | `2026/7/9 10:30` |
| `用户ID` | 用户唯一标识 | `KY_10000123456` |
| `会员等级` | 可选，用户会员等级 | `6` |
| `用户注册时间` | 注册时间，格式 `YYYY/M/D HH:MM` | `2026/1/29 23:40` |
| `弹次名称` | 弹次/系列名称，必须包含弹次编号 | `IP名称 第3弹` |
| `消费金额` | 订单金额（数值） | `39.0` |

## 分析框架

报告严格遵循以下分析框架：

### 报告章节结构

1. **执行摘要** — 5条数据驱动的核心结论
2. **新弹次销售概览** — 核心指标总览（各弹次上线天数、销售额、付费用户数、客单价、订单数对比表）
3. **新老用户分布** — 严格按注册时间二分类 + 老用户细分
   - 新用户定义：注册时间在新弹次销售周期内
   - 老用户细分为：历史注册·首次购买IP 和 历史复购用户
4. **跨系列复购分析**
   - 3.1 人群主导判断（历史复购 vs 首次购买）
   - 3.2 历史复购用户特征（购买深度、历史消费分层、消费模式）
   - 3.3 新付费用户特征（规模、客单价、首单分布）
5. **用户流失分析**
   - 4.1 流失规模（整体流失率、TOP200流失情况）
   - 4.2 高价值流失用户特征（消费层级分布、流失时点判断）
   - 高价值用户明细表（消费5000元以上的用户各弹次消费明细）
6. **策略建议** — 5条数据驱动的可落地运营建议
7. **附录** — 数据说明、指标定义

### 核心指标定义

| 指标 | 定义 |
|------|------|
| 上线天数 | 有销售额的最后日期 - 有销售额的第一日期 + 1 |
| 销售额 | 该弹次所有订单消费金额之和 |
| 付费用户数 | 该弹次有消费记录的独立用户数 |
| 客单价 | 销售额 / 付费用户数 |
| 订单数 | 该弹次所有订单数量 |
| 新用户 | 用户注册时间在新弹次销售周期内 |
| 老用户 | 注册时间在新弹次销售周期之前 |
| 历史复购用户 | 购买过新弹次且至少购买过1个历史弹次 |
| 流失用户 | 历史弹次有消费但新弹次未消费的用户 |
| 整体流失率 | 流失用户数 / 历史弹次付费用户总数 |
| 弹次内复购率 | 在该弹次内多次下单的用户比例 |

### 图表输出

当前版本输出纯文本Markdown报告，不包含图片图表。所有对比数据以表格形式呈现。

## 结果校验

每次生成报告后需要校验：
1. 确认新弹次被正确识别（最后一列为新弹次）
2. 检查核心指标数值是否合理
3. 确认流失率等敏感指标有数据窗口说明
4. 表格格式是否对齐
